Validation Pipeline // 8-Stage Fail-Closed Ingest

Evidence Pipeline แบบ Fail-Closed

หลักฐานทุกชิ้นต้องผ่านการตรวจสอบทั้ง 8 ขั้นตอน หากพบข้อบกพร่องแม้แต่จุดเดียว ระบบจะปฏิเสธทันที

STAGE 01
Artifact Existence
อ้างอิงไฟล์ซอฟต์แวร์หรือผลจำลองที่มีอยู่จริงในคลังโค้ด
Missing File → Reject
STAGE 02
SHA-256 Digest
คำนวณแฮช 64 หลักเพื่อรับประกันว่าไฟล์ไม่ถูกดัดแปลง
Invalid/Fake SHA → Reject
STAGE 03
Timezone-Aware UTC
บันทึกเวลาสากลพร้อมระบุโซนเวลาชัดเจน (ISO-8601)
Naive Timestamp → Reject
STAGE 04
Role & Source
ระบุบทบาทผู้รับผิดชอบและขอบเขตที่มาของเอกสาร
Empty Role → Reject
STAGE 05
Redaction Status
ยืนยันว่าข้อมูลผ่านการตัด PII ด้วยสถานะ PASS
PENDING/FAIL → Reject
STAGE 06
Zero-PII Filter
สแกนห้ามมี HN, AN, MRN หรือเลขบัตรประชาชน
Raw HN Reference → Reject
STAGE 07
Forbidden Claims
ป้องกันคำอวดอ้างเกินจริง เช่น CLINICAL_VALIDATED
Overclaim Marker → Reject
STAGE 08
Chain of Custody
ผูกโยงรหัสหลักฐาน (Unique ID) เข้ากับลำดับการส่งมอบ
Duplicate ID → Reject
Fail-Closed Guarantee: หากมีข้อผิดพลาดในด่านใดด่านหนึ่ง หลักฐานจะไม่สามารถเข้าสู่แฟ้ม Dossier ได้โดยเด็ดขาด
gv10_evidence.py :: EvidenceEntry.validate()
Security Control: Automated Ingestion Gatekeeper
Evaluation Mode: Deterministic & Immutable
